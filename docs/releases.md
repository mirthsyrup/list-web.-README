# Выпуск версий

1. Менять актуальные исходники в `site/` и запускать `npm test`.
2. Сформировать ZIP и iOS HTML из тех же исходников:
   `python3 scripts/build_release.py --version 2.8.6 --out out/release-2.8.6`.
   Перенести ZIP в корень репозитория. Предыдущий активный ZIP пока оставить
   доступным по прежнему пути: его может запросить закэшированный загрузчик.
3. Обновить номер ZIP в публичном `index.html` и номер версии в метаданных.
4. Проверить исходники против ZIP: `npm run check:release`.
5. Проверить сайт на телефоне, включая сохранения, импорт, экспорт и справочник.
6. Пакеты приложений строить из той же веб-версии. Сравнить содержимое
   `assets/web/` в APK и `Payload/List.app/web/` в IPA с `site/`.
7. Подписать приложения тем же способом и идентичностью, что предыдущую версию,
   и проверить обновление на устройстве с существующим персонажем.

IPA здесь содержит самодостаточный `web/ios-entry.html`: код, каталоги и стили
встроены в него для запуска нативной оболочкой через `file://`. Не удалять этот
файл и не заменять его обычной веб-страницей без проверки на настоящем iPhone.

## Компактная IPA

```sh
python3 scripts/optimize_ipa.py original.ipa out/compact.ipa
```

Скрипт создаёт отдельную копию и JSON-отчёт. Он удаляет внешние копии только после
сверки с уже встроенным содержимым. Рабочий HTML, нативный исполняемый файл,
права файлов, иконки и юридические материалы сохраняются побайтно.

Скрипт отказывается менять пакет с профилем provisioning, ресурсной подписью
или обычной дистрибуционной подписью. Такой пакет нужно пересобрать и подписать
штатным инструментом. Проверенная оригинальная IPA 2.8.5 содержит только
ad-hoc подпись самого исполняемого файла без подписанных ресурсов; установку
компактной копии выполнять тем же способом sideload/переподписания, что оригинал.

## Архивы

Предыдущие ZIP и отчёты лежат в `archive/`. Новые APK/IPA лучше хранить в Drive
или GitHub Releases, а в Git — исходники, проверки и метаданные. Для уменьшения
существующей истории Git потребовалось бы её переписывание; это здесь не делалось.

## Проверка анимации в настоящем браузере

Дополнительно к `npm test` можно выполнить:

```sh
node scripts/check_motion_browser.cjs site /path/to/previous/motion-ui.js out/motion-browser-results.json
```

Скрипт требует Playwright и Chromium. Путь к модулю можно передать через
`PLAYWRIGHT_MODULE`, к браузеру — через `LIST_CHROME` (по умолчанию `/usr/bin/chromium`).
Он проверяет разворот анимации, прокрутку внизу страницы, переход между вкладками
и уменьшение движения. Счётчики Layout/RecalcStyle позволяют сравнить работу
браузера; это не измерение частоты кадров физического iPhone или Android.

## Проверка отклика действий

```sh
node scripts/check_feedback_browser.cjs . out/feedback-check
```

Скрипт открывает публичный ZIP-загрузчик; вместо `.` можно указать извлечённую
`assets/web` из подписанной APK. Проверяются фактические изменения обычных и
временных ОЗ, ограниченное лечение, отсутствие ложных эффектов, степени
результата по КС, ошибки ввода, настройки, обе темы и уменьшение движения.
OfflineAudioContext рендерит шесть встроенных звуков и проверяет сигнал.
Нативный мост в браузере подменяется: аппаратная вибрация требует устройства.
Android-патч и его JVM fixtures описаны в
[scripts/android-feedback/README.md](../scripts/android-feedback/README.md).
